> **Status 2026-10-02:** direction superseded by the platform plan `docs/plans/permission-model-v2.md` (§12 adopts this branch as its starting point); this note is kept unrewritten as the branch's history.

**Baseline preparation inventory; not release certification.** Observations and blockers below describe the preparation baseline, not the current implementation. See `workspace-access-modes-implementation-status.md` for subsequent bounded adapters and verified checkpoints. Read against `c555316a132860799a6a8fb366a97049bf861ff8` and `workspace-access-modes-and-migration.md`. Connector instances, grants, OAuth and provider exposure are deliberately delegated to the connector manifest. Ingest destinations, channel sessions and principal boundaries remain in this manifest.

## Reading conventions and proposed defaults

Paths below are repository-relative. In tables, `A/` = `packages/api/src/`, `C/` = `packages/core/src/`, `W/` = `apps/app-web/src/`, `M/` = `packages/api/migrations/`. Factory `.method` notation identifies returned store methods. Routes without a named callback are identified by file and HTTP path. Test references are existing starting points, **not evidence of passing tests or mode coverage**. Owners are proposed implementation lanes, not assigned people.

The following defaults are requirements from the parent plan, not descriptions of shipped behavior:

- **S (ordinary shared):** after preserving canonical parent/source, explicit private, Project and sensitivity floors, otherwise-unbound shared creation receives the active canonical default department. Persist resource and admitted labels atomically; missing policy/default or stale ambiguous intent blocks admission.
- **D (ordinary shared):** inherit a valid bound destination; otherwise accept an authorized explicit destination or suggest an unambiguous active/assistant default only where the family allows it. Ambiguity needs selection/protected holding. Never union everything the caller can read.
- **I (inherited/derived, both modes):** preserve source requirements and visibility; mode change is not a relabeling instruction. Revalidate after queued/external work. No automatic hold release.
- **P (principal/private, both modes):** no extra audience, membership, credentials or external-delivery permission merely because the workspace is Simple.

Omitted selection and explicit null/General must remain distinguishable. Existing `[]`, `null`, legacy access, General Teamspaces and all-assistant grants do **not** establish the proposed Simple guarantee.

- **Frontend:** `W/components/create-workspace-form.tsx`; workspace/settings member surfaces use direct `authFetch` as well as `W/lib/api/workspaces.ts` (the latter is not a canonical create/member SDK).

Do not describe these separate member-side writes as atomic default-department admission.
- **Expected:** Simple eligible members receive only the default department package in the membership transaction; Departments intended membership/pending setup, no silent conversion from legacy. Removal ends authority. External identities are not eligible solely because they exist.

## Admission completion and release blockers

1. **Atomicity/concurrency:** proposed `resource-admission.ts` is not present as an established guarantee. Choose policy-row lock/revision protocol and transaction plumbing for every canonical writer and side effect. Best-effort assistant/member/edge/goal hooks need explicit treatment. No locks across human/LLM/provider work.
2. **Intent/versioning:** freeze omitted vs explicit-null protocol and minimum API/worker/client version. Fresh unbound creation, historical null binding and replay are different operations. Add denial/refresh behavior before enabling Simple defaults.
