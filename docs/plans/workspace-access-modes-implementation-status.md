This is historical implementation evidence, **not completion or release certification**. The complete requirements remain in `workspace-access-modes-and-migration.md`, including AM01–AM22. No workspace is automatically activated as Simple by these changes.

## Implemented at this checkpoint

- Migrations 620–622: upgrade-compatible mode/default metadata, flat/default locality guards, atomic eligible Simple member/assistant bindings, durable migration records, encrypted pending connector setup, and separately reviewed `consolidate_default` source actions.
- Migration 623: permanent canonical-review-to-migration-item binding. Pause/cancel immediately blocks unapplied reviews even through the ordinary command endpoint; resume does not resurrect old confirmations. Receipt replay preserves applied changes. Expired item reviews can be regenerated under current policy.
- Migration 624: Project, Project membership, assistant audience/default/clearance, and assistant Project grant changes serialize with admission on the workspace row and advance policy revision. This also invalidates relevant saved reviews. These triggers do not grant additional authority.
- `workspace.default_department.set` is a canonical saved-review command: choose a local active flat destination without changing memberships, classification, or mode. Replacing an active Simple default is rejected.
- Principal and bounded resource migration items have current-admin inspection, exact saved review/apply, durable retry reconciliation, pause/cancel/resume, REST and attended Brian tools. Resource items reuse canonical scope review, one root per item, up to 25 items. Migration 626 permanently binds resource reviews to item lifecycle so ordinary canonical apply cannot bypass cancellation or supersession. Confirmation expiry is the returned migration confirmation expiry, not the underlying canonical review expiry. Inventory/intake/finalizer blockers remain explicit; applied items are **not** a completed migration.
- Source consolidation preserves private ownership, sensitivity and Projects; captures audience-scope evidence; checks expiry/policy/source/descendants; holds descendants; and rejects unsupported/held/history families. Bounded provenance-floor evidence covers derivations, predecessors, physical episode/task parents and link endpoints; apply revalidates it and checks the actual resulting departments exactly match the reviewed target. Unprovable/session-backed source evidence is rejected. Classified inventory is an explicit opt-in, so already labelled sources can actually be selected. The ordinary inventory remains unresolved/held by default.
- Task creation is the first production resource writer integrated with admission. Resolution precedes dedup within the writer transaction. Omitted Simple roots receive the common department; explicit empty/null intent cannot silently become that default. Departments requires an explicit or inherited destination. Parent tasks are read/locked through canonical predicates; privacy/ownership/sensitivity/department/Project floors survive. Legacy behavior remains compatible. Other writer families are not covered by this task adapter.
- Memory and episode creation now perform transactional admission with workspace-first locking. Validated memory lineage and locked episode parent floors survive default changes. Ready-mode episodes persist canonical `confidential` for legacy `private`/`secret` sensitivity aliases so SQL authorization and evidence agree; this does not change personal visibility or historical rows. Source IDs without validated memory derivation fail closed. Upstream transactions and source-binding ingress still need full audit.
- Canonical authored root workspace-file creation now admits in the insert transaction. Known generated/session/source-bound callers without validated provenance are explicitly blocked in ready mode, not guessed as shared. Higher-level byte staging, uploads/finalization, parent integration and other file/media writers remain unimplemented; this is not complete A04 coverage.
- Entity/link authored roots and canonical endpoint floors, plus manual knowledge roots, now have transactional admission. Unproven entity derivation and knowledge source/sync configuration remain blocked rather than receiving guessed destinations.
- Migration 625 enforces one-use, transaction-local creation receipts on seven content families: tasks, memories, episodes, workspace files, entities, links and knowledge entries. It checks the persisted envelope, actor, partition and current policy revision after inherited-scope triggers. Task/memory/file successor INSERTs also use admission; it is not a complete mixed-version backstop for all tables.
- Ordinary authenticated shared chat creation resolves scope and inserts in a workspace-locked transaction; resumed bindings are unchanged. Generic shared creation without trusted human provenance fails closed in ready mode. Public/channel/API/personal and direct-SQL session writers are not newly certified; sessions have no SQL backstop here.
- Authored page placement is a partial A05 slice: only separately supplied server-verified human provenance can default a ready-mode root to a Teamspace linked to the canonical department. Explicit private placement and current parent/Teamspace/Project/sensitivity floors survive. Missing linked defaults return an actionable blocker; writers do not provision access. Migration 627 provides narrowly scoped, membership-checked Teamspace row locking without granting UPDATE rights or locking unrelated workspaces. Seeded/generated/import/copy sources and unreviewed Teamspace creation remain blocked or unintegrated. Saved Views are not a canonical held-resource kind; actual source holds require their own adapters.
- Workflow/goal creation has a partial A09 transactional authoring adapter. Ordinary session-authenticated manual workflow REST creation preserves omitted selection, resolves the canonical primary and captures authority under the insertion transaction. Supplied consent is not renewed or enlarged; persisted run bindings remain unchanged. Ready-mode schedule/event/webhook REST creates reject before insertion, avoiding an orphan definition when schedule creation is unsupported. Goal creation requires trusted internal proof; source/autodraft/native/schedule adapters and edit/clone/enable revalidation remain open.
- Office shell storage has a bounded A06 adapter: separate trusted human-root proof, atomic workspace-first admission, exact persisted envelope and existing Office principal/operation checks. No production caller yet supplies that proof. Generated/import/template/copy/recovery paths remain blocked in ready mode or unintegrated; there is no Office SQL receipt backstop yet. Legacy injected-query store tests are not app-role authorization evidence.
- Migration 628 fixes ready-mode app-role changed-content memory successors. A memory-only wrapper rechecks the locked canonical predecessor, version and live actor/private/assistant/Project/mutation authority before holding descendants. Admission stamps the post-invalidation policy revision; holds, successor and tombstone roll back together. The generic cross-family invalidator remains unavailable to app callers. Reviewed declassification and broader derived-lineage producer coverage remain open.
- Pending connector setup currently provides staged credential isolation, exact target/policy/account-consent binding and transactional activation callbacks. Existing provider/connector production flows are **not** yet integrated; no Simple catalog exception is enabled.
- Admin migration UI shows actual mode/setup, saved plans, named principals/targets, before/after principal department reach, frozen resource impact/source-floor previews, exact confirmation, applied progress, expiry, pause/cancel/resume and explicit completion blockers. Resource apply replays the exact discriminated confirmation; stale/cancelled responses are not counted as applied and uncertain retries keep the original confirmation. Scope consolidation UI supports explicit classified inventory and saved evidence. Protected cache lifetimes and viewer/workspace invalidation apply. All four locales are implemented. This is not the final general mode selector or mode-aware creation UI.

An independent targeted review identified and then rechecked three corrected admission bugs: derived output could use a different workspace from admission when the workspace argument was omitted; assistant-only task/file rows incorrectly received the personal-resource exemption; inherited read-grant source floors incorrectly required mutation rights. Regression tests now reject the workspace mismatch before source locking, classify assistant-only work as shared while retaining its assistant partition, and separate live readable derivation floors from mutation-authorized additions/destinations. A second independent review found three concrete defects in the new slices: foreign legacy assistant pointers could bypass ready output-workspace session admission; legacy workflow capture could exhaust the embedded single-connection pool; assistant direct compartment ceiling changes escaped the admission barrier. All three were fixed and rechecked by the reviewer. Session admission now locks the actual output and assistant workspaces, rejects new cross-workspace ready writes, and locks resumed identities against deletion/reinsertion; all-legacy historical comment threads retain compatibility. Workspace-less assistants are already prohibited by the schema. Legacy authority capture now uses the insertion client, with real single-shared-connection regressions. The unpublished 624 trigger also serializes direct and default compartment changes. The reviewer also examined migration 628's memory-only invalidation wrapper and its integration for actor, version, private, assistant, Project, GUC and mutation-versus-read boundaries plus atomic rollback/current receipts; no concrete defect was found. These are bounded reviews, not full-product certification.

- **Migration orchestration:** canonical prepare/apply and projections now reuse the reserved advisory-lock connection, including real max-one-connection tests. Empty inventory-only plans remain `draft` across inspection and pause/resume, never counting zero items as applied.
- **Inventory (631):** 58 fixed metadata-only family adapters, durable bounded reconciliation, content-free hashes, deletion tombstones, before-cursor insertion detection, protected browsing and explicit coverage blockers. A quiet family is not a global snapshot or intake certification. Existing stale policy fingerprints require a fresh plan.
- **Connectors (629):** authenticated setup routes are wired in standalone boot with encrypted nondiscoverable credentials, exact account/root consent, transactional create/same-account reconnect/share/grant-free transfer and publication backstops. Reconnect preserves the exact stored department/Project envelope, ownership and sensitivity; neither callback nor retry silently activates or shares.
