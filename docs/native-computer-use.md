## Implemented path

`This computer` in Electron (`/w/:workspaceId/computer/native`) selects an existing assistant, conversation, task and native window. Main creates an authenticated, PKCE-bound session, asks local consent, exchanges its private verifier for a distinct native token, waits for relay readiness, and, for control grants, starts the approved goal through the API. Tokens, grants and verifier never enter the renderer. The assistant also has a separately governed `nativeComputerTask` tool; both control paths share a durable one-run claim.

With `allowControl=false`, this is instead a **one-shot local AX inspector**: pairing and local consent precede one main-created observe of the selected window. Main then kills the helper/releases the lease, closes relay authority and awaits API revocation before returning a bounded, redacted local snapshot. No model task or screenshot runs; API run/binding and API or relay-delivered execution cannot use an inspector grant. Cleanup/identity failure withholds the snapshot. Window display labels are local discovery metadata, separate from the five-field authority target (`appId`, `processId`, `processInstanceId`, `windowId`, `windowInstanceId`); forged renderer labels are ignored in favor of main’s helper-discovered label and never enter grants/API/relay.

- `packages/computer-control`: strict versioned identity, target, observation, action and receipt schemas; bounded messages and coordinate transforms.
- `packages/core/src/computer-use`: AX-first bounded candidates, existing Hydra/Jev routing, generation when AX candidates are insufficient, configured LLM recovery, optional vision grounding, progress verification, stale-state refresh and no replay after an unknown outcome.
- `packages/api/src/computer-use`: live scope/capability/auth-session checks, tool policy, configured workspace/custom-provider routing, metering and conservative budget reservations.
- `apps/browser-relay/src/native-relay.ts`: isolated `/native-computer-v1` namespace, native-audience tokens, device lease, heartbeat and dispatch fencing. Existing `/ext` browser connections are unchanged.
- `apps/app-desktop/src/computer-control`: serialized broker, cross-instance local lease, private helper pipes, exact local action approval, helper termination and local-only restart.
- `apps/app-desktop/native/computer-control`: Swift AX, .NET UIA and Python AT-SPI/X11 helpers and local fixtures. Each action rechecks live process/window identity, consent, lease, epoch, deadline, geometry and current observation.

### Deliberate current limits

Historical removed-emitter boundary: input was unconditionally disabled and macOS operations were probe-only. The semantic/capture implementation and gated ownership candidate above supersede that source boundary, but native acceptance remains open and no platform is accepted for input. P5 is not complete. It must release only owned presses, survive helper/parent death, and prevent late events or a new owner until release is confirmed. Test partial delivery, physical press/release overlap, takeover, Stop/kill at every down/up boundary, guardian failure, blocked workers, lock/sleep, deadline/relay loss and lease reacquisition on real native systems. Do not weaken attribution, Stop or lease requirements. Source checks and cross-compilation/parsing are not native acceptance. macOS separate down/up posts had no owner surviving SIGKILL/`_exit`; Windows unconditional finally-up could release a physical press and could be bypassed by termination. Both emitters were removed.


- **TextEdit:** document AX inspection and non-secret text-area assignment only, not menus, security dialogs, arbitrary shortcuts or external effects.
- **Fixture:** Bounded semantic actions plus scoped capture for its isolated `Brian Safe Canvas` window; coordinate clicks are refused on all platforms. The helper checks the safe content cohort, window geometry/occlusion and frame identity. It never captures the full desktop. TextEdit/Notepad/gedit screenshots are refused.
- Multi-step completion requires fresh AX evidence matching all frozen whole-goal postconditions; replanning cannot drop unfinished objectives. Canvas counters/results remain for future click verification, but no production helper enables clicks. A unique generated candidate skips a redundant selector. Fixture selection, semantic scroll and menu/dialog workflows are expanded, subject to each helper’s supported cohort. Effects without reliable postconditions pause; this is not an arbitrary multi-application planner.
- Focus restoration is part of local consent: the exact selected window is brought forward at session start and after an approved action dialog; unchanged handles/semantics/geometry are rechecked. There is no model-callable unrestricted focus operation.
- Arbitrary keys, drag, clipboard, credential access, shell/script execution, elevated/security surfaces, unattended operation and remote takeover are not enabled. Scroll is restricted to supported fixture semantic controls, not generic wheel input.
- A complete accessibility tree can still omit a canvas target. With no usable AX candidates, the loop may request capture, but both API policy and the local helper must independently allow it; the CV loop additionally requires input capability, which no production helper advertises.

## Stop, privacy and recovery

Stop now destroys both private command and observation streams **before** attempting kill. Channel closure independently revokes helper authority, including buffered commands: watchdogs and read/capture, focus-restoration and pre-effect guards detect closed endpoints. Closure is **not process-death proof**; the lease stays held until actual exit or proven never-spawned state. Real Linux pipe/socketpair tests exercise the portable checks; actual Windows/libuv pipe-state query acceptance remains open and unsupported/query-failure cases refuse authority. No guard can retract an OS operation already entered.

The helper-client death barrier resolves only on actual process exit or a proven never-spawned process. A kill returning false, throwing or emitting errors revokes authority but does not release the lease; repeated errors remain handled safely. Stop is not proof of death, and uncertain termination cannot authorize a new owner.

An always-on-top local indicator shows application and AX/vision perception; tray Stop and **Cmd+Shift+Escape** on macOS / **Ctrl+Alt+Shift+Escape** on Windows/Linux remain independent of the task renderer. The latter avoids Windows’ reserved Task Manager shortcut. Helpers launch with `windowsHide: true` so a console cannot steal focus. Exact local approval displays full action parameters and target/ancestor control context, not just a label. Missing emergency shortcut or helper capability prevents start. Sign-out, identity/workspace/deployment changes, lock/sleep, helper death, physical takeover, permission loss, lease expiry and relay loss end authority. Polling never starts work. Discovery after Stop may inspect available targets, but control requires another explicit user start and fresh consent/epoch.

Secure/unknown AX subtrees are locally redacted. Raw observations, screenshots, generated text and goals are ephemeral, not audit records. Metadata audits contain lifecycle and action IDs/kinds/outcomes/codes plus inference-attempt metadata, not prompts or responses. Model prompts treat UI content as untrusted data. A successful OS input call is not proof of task completion.

Before dispatch, the API durably marks the outcome uncertain. A missing/invalid receipt, process death or unknown delivered outcome preserves the fence. Neither model fallback, reconnect, expiry nor ordinary DELETE clears it. Only an authenticated matching `not_executed` / `stale_observation` receipt for a ref action permits bounded fresh-observation recovery. It never replays the old command, drops frozen whole-goal objectives or resets committed progress. Missing/unknown receipts remain fenced. One run per grant prevents goal replay. Completed runtime closures are discarded, not permanently cached. Foreign keys detach deleted user/workspace/conversation/task metadata rather than blocking ordinary deletion; unresolved device evidence remains for human reconciliation.

The parent lease derives its fixed home from OS `userInfo().homedir`, never `HOME`/`USERPROFILE`. Linux independently authenticates the system-logind session owner and uses `User.RuntimePath`; unsafe/missing paths or an `XDG_RUNTIME_DIR` mismatch fail closed. Environment-selected directories cannot split device authority.

Public Stop/disconnect responses redact prior identity/expiry; integration-level Stop erases the private grant. Stale controller callbacks are ignored, without releasing a live helper’s lease: helper death remains the release barrier. A completed inspector snapshot is retained only under its authenticated account/workspace/generation binding, not exposed as cross-account stopped status.

Windows uses an exclusive per-user named-pipe exclusion slot carrying **no control messages**, plus the helper’s independent mutex and parent-death watchdog. A main-process crash closes the slot; that is not authority to replay unknown work. POSIX stale-directory lease behavior is unchanged: no automatic stealing.

POSIX local lease crash recovery and server `execution_unknown` / interrupted `run_state` reconciliation are operator-only: first terminate/verify absence of helpers, inspect the affected application's actual state with the user, retain an audit of the determination, and only then retire the exact lease record. There is no automatic stale-lock stealing or model-callable clearing endpoint. Do not clear an unknown fence merely to retry a task.
